# Tour 1 — QA — bascule-editeur it2

RISQUE — Deux fronts où l'instrument existe mais la cible qu'il doit viser n'est pas encore nommée. (a) `FORME_ID_DOSSIER` (KR-177) est un `const` privé de `validate.ts`, non exporté : un test unitaire sur `createDossierId()` devrait recopier le regex en dur, ce qui dérive du contrat le jour où `validate.ts` se resserre — même défaut que celui que KR-117 interdit pour les autres tables. (b) `EditorTopBar` (KR-109, chrome partagé) est câblé Livre : `nodeCount` et `onAddNode` (→ `books.addNode`) n'ont pas d'équivalent Dossier. Le réutiliser tel quel pour « l'écran minimal » sans dire ce que devient ce slot produit soit un compteur inventé, soit un bouton mort — l'affordance qui ment que `design_contract.etat_vide_section` interdit ailleurs dans cette même feature.

OBJECTION — Le critère « … l'auteur atterrit sur l'écran d'édition qui s'ouvre dessus (écran minimal) » ne nomme aucun marqueur observable. jest+RTL peuvent trancher un rendu, mais seulement une fois écrit ce qui doit apparaître (titre du dossier dans un `<h1>` ? `nodeCount`/« + Nœud » masqués plutôt que simulés ?) et quelle route (`router.current()`) en résulte. Tel qu'écrit, aucun test ne peut être posé contre cette ligne — pas faute d'outil, faute de cible nommée.

PROPOSITION — (1) Exporter `FORME_ID_DOSSIER` (ou le faire migrer dans `identifiers.ts`, déjà source des autres formes) pour que le test de `createDossierId()` l'importe au lieu de le recopier. (2) Nommer explicitement le contenu de l'écran minimal : titre du dossier affiché, `nodeCount`/« + Nœud » **omis** (pas de valeur inventée), testable par `queryByRole('button', {name:/nœud/i})` absent. (3) Élever KR-071 au rang de critère d'acceptation écrit (il n'y figure pas aujourd'hui, seulement dans `open_questions`) avec un test nommé, puisque le grep prévu à l'itération 3 ne le voit pas.

VERDICT — recevable sous réserve (export de `FORME_ID_DOSSIER`, contenu de l'écran minimal nommé, KR-071 promu en critère testé).

## Annexe — tests nommés

Patron déjà en place (`exportDossier rend le document re-validable`).
- `identifiers.test.ts` ou `DossierService.test.ts` › « createDossierId() matche FORME_ID_DOSSIER, jamais createId() générique (KR-177) » — nécessite l'export proposé ci-dessus ; sinon le test dérive une copie du regex, ce que je ne compte pas comme vérifié contre la source de vérité. Cas limite : id ne contient jamais `_` (le séparateur de `createId()`).
- `createFlow.test.tsx` (repointé sur dossiers) › « creates a dossier … firing events in order (KR-004) » — même patron `order: AppEventName[]` que la version Book actuelle, assertion `expect(order).toEqual(['dossier:created', 'dossier:opened'])`.
- Test nouveau (écran minimal) › « ouvre l'écran d'édition sur le dossier créé » — `expect(router.current()).toEqual({name:'dossier', dossierId: d.id})` + `screen.getByRole('heading', {name: d.titre})`.
- Test nouveau (EditorTopBar/EditorScreen dossier) › « Aperçu du jeu visible mais désactivé, message nommé feature n°9 » — mécanisme déjà précédenté (`EditorTopBar.tsx:93`, `title` sur bouton désactivé) : `const bouton = screen.getByRole('button', {name:/aperçu du jeu/i}); expect(bouton).toBeDisabled(); expect(bouton).toHaveAttribute('title', expect.stringContaining('feature n° 9'))`.
- Test nouveau (KR-071) › « un dossier ouvert dans l'éditeur et supprimé renvoie à l'accueil ; book:deleted n'est plus le déclencheur » — monter `<App/>`, naviguer sur la route dossier, `dossiers.remove(id)`, `expect(router.current()).toEqual({name:'home'})` ; test complémentaire de non-régression : `expect(readFileSync('src/App.tsx','utf8')).not.toContain(\"'book:deleted'\")` (le grep KR-181/it3 ne le couvre pas, il ne cherche que `books.`/`BookService`/`TreeCanvas`).

- Cas limite double soumission : absent aujourd'hui côté Book comme côté Dossier — `await user.dblClick(creer)` puis `expect(dossiers.list()).toHaveLength(1)`.
- Si le comité retient la réouverture par clic (question ouverte du cadrage) : « cliquer une carte lisible navigue sur la route dossier et émet dossier:opened » ET « une carte illisible ne porte aucune affordance de clic (pas de `role=button`/`tabIndex`, `{Enter}` sans effet, `router.current()` inchangé) » — sans ce second test, un dossier illisible cliquable serait un incident silencieux, pas une régression détectée.
